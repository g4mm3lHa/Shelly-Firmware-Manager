# Code map – backend modules

Part of `docs/CODEMAP.md`; read when you change `shelly_firmware_manager/app/*.py`.

**Names and line numbers are not kept here.** Generate them from the source, always current:
`python3 tools/dev/symbols.py <module>` (classes, functions, constants with line and first
docstring line), `-g <text>` filters by name, `-c` lists classes and module functions only.
Then read the symbol with `sed -n '<line>,+40p' <file>`. This file keeps only what a script
cannot know: responsibility, layering, invariants and pitfalls.

## Modules (`shelly_firmware_manager/app/`)

| Module | Responsibility and pitfalls |
|---|---|
| `main.py` | start (options: `load_settings`, first start takes over the options the Supervisor kept and empties them), servers, scheduler loops (`run_schedule`, `run_timetable`), backup check in the background, clean stop. `VERSION` must equal `config.yaml` (`bump.py` sets both). |
| `data_paths.py` | paths below `/data`; always read as `data_paths.NAME` (tests and the demo redirect them). `write_atomic`: the one way to replace a file there (temporary file, optional fsync and mode 0600, rename); only the state file has its own save (`state.bak`). |
| `shelly.py` | all device access: errors (`ShellyError` and its kinds; `device_error`: a Gen2+ error object as "message (code n)", a leading copy of the code in the message dropped; `ap_refusal`: readable text of a refused access point form – an open access point after a password, other code -103 –, the device answer in brackets), text helpers for outside values, authentication (`DeviceAuth`; `protection_status` returns `Protection`: `enabled`, Gen2+ `device_id` and the raw `auth_domain`, its `realm` is a valid `auth_domain` with the same MAC suffix while protected – a password set under the 2.2.0 ID of a 1PM Mini Gen3/Gen4 –, else the ID; `same_device` compares the MAC suffix of the ID with a known ID or MAC; `Shelly.SetAuth` always gets the device ID; a sign-in block, HTTP 429 or RPC code 429 while credentials are stored, raises `AuthBlockedError`, a subclass of `AuthError`: one wait of `AUTH_BLOCK_WAIT_S` only before credentials were sent, a signed request is never repeated, HTTP and WebSocket alike; the optional requests of a settings read re-raise it), requests with redirect and size guards (a redirect is never followed or read as an answer; one to HTTPS/WSS raises `HttpsRequiredError` – Enhanced Security, severity error like `AuthError` –, any other names its status; the target is never shown), settings read/write, OTA WebSocket, `fetch_test` (device fetches a URL via `HTTP.GET`), `port_open`/`answers` (Try again). `shelly_net` and `shelly_cloud` build on it, never the other way round. |
| `shelly_net.py` | device addresses: `resolve_device_origin` pins one checked IP; only `LAN_NETWORKS` (RFC 1918, `fc00::/7`), never extended; host names only looked up for display; `resolve_lan_address` gives the LAN IP of a host for the host port check (`None` if any address is outside the LAN). |
| `shelly_cloud.py` | manufacturer servers: offers (Gen2+ per firmware ID, Gen1 one list), changelog pages, downloads; shelly.cloud only, every redirect hop checked, size limits, SHA-256 of the URL enforced; firmware file name rules (`FW_NAME_RE`). |
| `web_ui.py` | Ingress UI and JSON API in `build_ui_app`: middleware, page, state and the route table; handlers per area in `web_devices.py`, `web_firmware.py`, `web_backups.py`, `web_schedules.py`, `web_settings.py` (classes on `web_base.Handlers`; a synchronous manager call goes through `translated`, an awaited one through `guarded`); middleware for CSRF, JSON depth/size, security headers, unexpected error → 500 without details. "(beta)" mark only on pre-release versions; the page carries the saved option `base_color` on its root element (`data-base-color`, default for an unknown value). |
| `download_server.py` | GET/HEAD `<sha256>.<ext>` for the Shellys, only during an active update, by default only to the target IP; GET/HEAD `connection-test/<32 hex>` only during a connection test the user started, only to its device, once, a short text (`Installs.test_fetched`). |
| `schedule.py` | the automatic check: every N days at HH:MM, HA time zone, DST, catch-up. |
| `timetable.py` | schedules and the time of "Install at": validation and next run, pure functions; stored entries re-checked at start (`check_stored`, `check_plan`). |
| `app_options.py` | option validation (ranges, switches, choices `CHOICES` such as `base_color`; `NO_RESTART` / `needs_restart`: options saved without an app restart), merge with defaults, log diff, download URL rules, settings file (`read_settings`, `write_settings`, `take_over`). |
| `events.py` | activity log (JSON Lines): severity, entry IDs, delete/clear, `latest` mark. |
| `diagnostics.py` | text of "Details for a bug ticket" (`report`): masks names, IPs, MACs and Shelly IDs; values come from `Manager.device_report`, passwords never reach it. |
| `credentials.py` | per-device passwords, file 0600, Gen2+ HA1 only with its realm; a write error raises `ShellyError`. |
| `changelog.py` | Shelly changelog pages → plain text (parsed in a worker thread). |
| `store_transfer.py` | store export/import files as pure functions run in a worker thread: ZIP with sealed `manifest.json` (HMAC-SHA256, key = scrypt of the export password), `SHA256SUMS.txt`; every entry checked, ZIP64 refused. |
| `backup_store.py` | backups of device settings as files (no device or network access): header + zlib payload, encrypted with a standard-library key stream, HMAC tag (encrypt-then-MAC); decrypted only after the tag was verified. Stored files use the app key, downloads and exports a key from their password (key derivation `SCRYPT`/`derive_key`/`kdf_salt` shared with `store_transfer`). The key file is never overwritten (wrong size → `key.damaged-<time>`, unreadable → backups off, `KEY_UNREADABLE`); the tags of the listed files are checked in the background after the start (`verify_in_background`, batches of `VERIFY_BATCH`; `entries`/`warning` check the rest first; a file the key cannot open is not listed but keeps its index row, `_hidden`, so its marks come back with the matching key). Imports go through `clean_imported` (digest from the content, no future time); a store import writes files with `write_many` (worker thread), then `list_many` (index once). |
| `shelly_backup.py` | device side of a backup: `read`, `compare`, `restore` (chosen parts, device read again, only what it then reports counts as applied, restart when a part asks). Secrets (`SECRET_KEYS`) and the Home Assistant Bluetooth proxy script are never part of a backup. |
| `tls.py` | certificate pinning for `*.shelly.cloud`. |

## The manager

One object built from nine layers: each module holds one class that extends the class of
the layer before, so a layer only uses what lies below it (no imports upward). Everything
outside uses `manager.Manager` only. Constants live where they are used; tests patch them there.

| Layer / module | Class | Content |
|---|---|---|
| 1 `manager_core.py` | `ManagerCore` | state, `__init__`, options, persistence (atomic save, `state.bak`, damaged file → `state.damaged` warning), Home Assistant registry/area registry/version/notification/Supervisor calls (the list requests of one check over one WebSocket: `_ha_reads` scope with `HaConnection`, finished at its end; device registry, battery set and areas reused for `HA_CACHE_S` = 60 s by `_ha_cached`, single flight per key, failures never kept; full check and Try again read anew), check slots (`reserve_check`: "all" is exclusive, a device refused while checked/installed/reloaded, nothing while an import stores or a schedule runs), `STATUS_*`/`SECTION_*`/`SOURCE_*` constants, `severity_of`, `unexpected_text`, first-start state; `Pending`: what a dialog holds under a token (upload, store import/export, backup download/import): a wrong token drops nothing, the time drops it by a timer (`on_drop` removes its file), `take` uses it up. |
| 2 `manager_store.py` | `FirmwareStore` | firmware files and their metadata: registering, adopting unlisted files by content (never deleting), integrity, the rule when a stored file replaces a download (`_replaces_download`, `_stored_firmware`, `_store_offer`), downgrade candidates, manual delete with locks. |
| 3 `manager_transfer.py` | `Transfers` | files into and out of the store: transfers in parts (`PART_MAX` 8 MiB: Ingress refuses 16 MiB), upload (staged, then confirmed), store export/import (single-use tokens, checked completely before anything is stored). |
| 4 `manager_devices.py` | `DeviceSettings` | device settings read/write with read-back (`not_applied`; access point form `ap_config`, log diff without the password and without unchanged values, a refusal of the Shelly logged and raised with the readable text of `shelly.ap_refusal` – only for the form sent alone –), reload, restart, ignore, remove from list, device passwords (single and several; a refused or blocked Gen2+ `Shelly.SetAuth` is not verified further – no more signed attempts; a block during the verification is no rejected password; the live Gen2+ device ID is taken only with the same MAC suffix as the known ID or MAC; "store" tests the `Protection.realm` and, if refused, once more the device ID – only the candidate of the challenge realm signs). |
| 5 `manager_backups.py` | `Backups` | backup store and runs (before installation, manual, schedules), views, restore with preview and parts, password-sealed download, import per device. A failing backup before an installation stops that installation; a sign-in block is noted as `failed`, not `password`. `compare_after_update`: device read 15 s after an update with a "Before update" backup, result in `after_update`, log entry with the names of the changed settings only (`changed_keys`); never raises, writes nothing once the device installs again. |
| 6 `manager_checks.py` | `Checks` | full check (global lock) and single checks (parallel); scanning removed and other Shellys, Home Assistant listing (one `_ha_reads` scope per check, ended before device access), per-device offer logic: Gen1 store first then the manufacturer list; Gen2+ server decides (`_step_offer`, intermediate versions; activity `server` while waiting for it, `_asking_server`), beta, store fallback on server error, reference request, hold-back (`offer_after_days`), `keep_installed`; one shared provision per type and version (`_provide`); areas from the area registry (`_apply_areas`, kept when it cannot be read), `unreachable` mark, `probe_device` (Try again: answers, ports, no check). |
| 7 `manager_installs.py` | `Installs` | approved install (`approval_matches`), restart-and-install (`_back_after_restart`, also `restart_watched` / `watch_restart` of the row), Gen2+ WebSocket `Shelly.Update` / Gen1 HTTP, waiting for the exact target version via OTA events or polling, failure and retry, downgrade, step check after a confirmed intermediate version, download-server support; `run_connection_test` (one test at a time, the device fetches the test address). Weak Wi-Fi: pre-check and update command tried again while the device does not answer (`_command_update`; restart or lost connection by the running time of `shelly.link_status`, read by `_read_link` – a refused or blocked sign-in there stops the installation before the command), longer stall limit with a weak signal; the running step per device in memory (`install_steps`, `install_step_view` → state field `install_step`). |
| 8 `manager_schedules.py` | `Schedules` | "Install at" plans (run, lapse, missed – never made up) and schedules (create/update/delete, runs, left-out devices with reason), start-up clean-up (withdraw betas, strike unknown device IDs), notifications. |
| 9 `manager.py` | `Manager` | `public_state`: the only fields the UI sees; add a field there when the UI needs one. `device_report`, `hide_getting_started`. |

## Pitfalls
- State fields not listed in `public_state` never reach the UI; stored fields are described in `data.md`.
- A new check or install path must respect the slot rules of layer 1.
- A new Home Assistant list request goes through `_ha_list` inside the check's `_ha_reads` scope; reused answers are shared – never change a registry entry.
- Anything new that reads a file or URL from outside needs a size limit and goes through the guards of `shelly.py` (devices, addresses from `shelly_net.py`) or `shelly_cloud.py` (manufacturer).
